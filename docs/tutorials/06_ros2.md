# 6. Run the radar in ROS 2: build, launch, read the topics

The `ros2/` folder holds two colcon packages, `raw_radar_msgs` and `ti_radar_connect`, that run the same C++ driver as a ROS 2 node. The driver is compiled in by CMake; there is nothing else to install. The package reference (topics, launch arguments, SAR metadata) is [`ros2/README.md`](../../ros2/README.md). This tutorial follows it end to end.

## Prerequisites

- Ubuntu 24.04 with ROS 2 Jazzy: follow the official [install guide](https://docs.ros.org/en/jazzy/Installation/Ubuntu-Install-Debs.html). `sudo apt install ros-dev-tools` (in that guide) provides `colcon`. If you are new to ROS 2, do its [beginner tutorials](https://docs.ros.org/en/jazzy/Tutorials/Beginner-CLI-Tools.html) first.
- `g++` and `cmake` ([tutorial 1](01_install.md)); the host settings and a flashed board from [tutorials 2](02_host_setup.md) and [3](03_flash_a_radar.md).

## Build in a plain workspace

```bash
mkdir -p ws/src && cd ws/src
git clone https://github.com/davidmhunt/CPSL_TI_Radar.git
git -C CPSL_TI_Radar submodule update --init CPSL_TI_Radar_cpp/include/json
cd .. && source /opt/ros/jazzy/setup.bash
colcon list --base-paths src        # expect exactly raw_radar_msgs and ti_radar_connect
colcon build --base-paths src --symlink-install
source install/setup.bash
```

`colcon list` prints the two packages (`CPSL_TI_Radar_cpp/COLCON_IGNORE` keeps the C++ tree from showing up as a third); the build ends with `Summary: 2 packages finished`. Only `include/json` is needed ([why](01_install.md#clone-and-build)).

## Launch a radar

Copy a system JSON into the clone's `config/user/`, edit `cli.port` and `serial_stream.port` ([tutorial 5](05_driver_cli_and_adc.md)), and pass its **absolute path** (the launch default is a SAR config, and a bare name must be one installed under `share/ti_radar_connect/config/system/`):

```bash
cp src/CPSL_TI_Radar/CPSL_TI_Radar_cpp/config/system/IWR1843_demo_tlv_default.json src/CPSL_TI_Radar/CPSL_TI_Radar_cpp/config/user/my_1843.json
ros2 launch ti_radar_connect connect_ti_radar_launch.py \
    config_file:=$PWD/src/CPSL_TI_Radar/CPSL_TI_Radar_cpp/config/user/my_1843.json radar_name:=Radar_0
```

A node that cannot load its config or open a port logs the reason (for example `open_failed: cannot open the serial data port ...`) and exits 1. The arguments are listed by `ros2 launch ti_radar_connect connect_ti_radar_launch.py --show-args`.

## Read the topics

In a second terminal (`source /opt/ros/jazzy/setup.bash; source install/setup.bash`):

```bash
ros2 topic list                                  # Radar_0/radar_config_path, plus the data topics below
ros2 topic hz /Radar_0/detected_points           # serial point cloud (sensor_msgs/PointCloud2)
ros2 topic echo /Radar_0/radar_config_path --once
```

A config with `dca1000.enabled` publishes `/Radar_0/adc_data_cube` (`raw_radar_msgs/ADCDataCube`, int16 `real_data` and `imag_data` arrays) instead of, or beside, the point cloud. Do not run the node and the GUI or CLI on the same radar at once: one process owns a board's ports.
